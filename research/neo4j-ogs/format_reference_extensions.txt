
  Extensions
Extensions hold information tools need alongside the ontology, such as data sources and mappings for importing data,
diagram layout, and custom data.
Custom data
Many objects have a custom field, directly or under their extensions, for any other data to keep with the model. The
specification gives it no meaning. Grouping data under a key named after the tool or organisation that writes it avoids
clashes with data written by other tools.
nodes:
  person:
    label: Person
    extensions:
      custom:
        acme:
          owner: catalogue-team

Mapping
A mapping from a data source table to the graph. Either a node, relationship or query mapping.
One of node mapping, query mapping, relationship mapping,
chosen by its type.
Node mapping
Maps rows of a table to nodes.
 | 
 | Field
 | Type
 | Required
 | Description
 | type
 | NODE
 | Yes
 | Always NODE.
 | node
 | string
 | Yes
 | Id of the node being mapped.
 | table
 | string
 | Yes
 | Id of the source table.
 | properties
 | map of property mapping
 | Yes
 | Mappings from property ids to source columns.
 | mode
 | mapping mode
 | No
 | Whether nodes are merged with existing nodes or always created.
 | match_label
 | string
 | No
 | Label used to match existing nodes.
 | key
 | list of strings
 | No
 | Ids of the properties which identify a node.
 | depends_on
 | string
 | No
 | Id of another mapping in the same list which must be imported before this one. Empty when
there is no dependency.
 | id
 | string
 | No
 | Optional id of this mapping, so other mappings in the same list can reference it in depends_on.
